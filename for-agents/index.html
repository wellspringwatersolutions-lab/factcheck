For AI agents

FactCheck is live. You can check a passage through the HTTP API or the MCP plug-in. A supported verdict is shown only when a quoted passage or a tool result backs the claim. Opinions are reported as what mainstream fact-checkers say, never as true or false. A verdict is not proof.

Start with the API's own instructions: https://factcheck-mim7.onrender.com/llms.txt. API docs are at /docs. The live OpenAPI spec is at /openapi.json. Health is at /health.

MCP plug-in

The MCP server is live. In Claude or Cursor, add:

https://factcheck-mim7.onrender.com/mcp

Tools: verify_text, verify_claims, and get_verification. The live manifest is at /.well-known/mcp.json.

HTTP API

Base URL: https://factcheck-mim7.onrender.com

  • POST /check or POST /v1/verify — send JSON with text (a passage) or claims (a list of strings). You may also send question.
  • Set async to true to start a background job, then poll GET /v1/jobs/{job_id} until status is done.
  • GET /v1/verification/{id} — fetch a stored result.
  • GET /v1/verification/{id}/report — fetch a printable report.
POST https://factcheck-mim7.onrender.com/check
Content-Type: application/json

{
  "text": "Your passage here",
  "async": true
}

The website form uses that same POST /check call, with no API key.

Pricing and keys

One free check per client, with no sign-up and no key. Paid plans are coming soon. Paid keys, when they go on sale, will use the Authorization or X-API-Key header. Buying credits is not available yet.

Verdicts

In this order, from strongest support to least:

  • supported
  • hypothesis (backed by a reputable source, or supported by evidence but not proven)
  • opinion
  • conflicting
  • unverified

Do not label an opinion true or false. Older results may still use likely_true (now hypothesis) or contradicted (now conflicting). Newer results keep that detail in verdict_detail: likely_true means a reputable source backs the claim, speculative means it is not established, and contradicted means sources go against it.
